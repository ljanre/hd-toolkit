# kcorr quality review and performance checks · 15 October 2026

No numerical regression was found in the tested calculations. Comparisons use the repository version before the manual-kcorr features (`0ec14af`), not a new implementation of the formulas.

## Calculation control

- Eight protected engineering source files match their pre-feature SHA-256 hashes: foundation tables, Figure 3.3 engine, range extension, loss-of-support correction, traffic engine, rigid subbase, swept-path geometry and workbook curve widening. The complete rigid calculation core also matches exactly.
- **875 foundation/correction combinations** produce exactly the same composite k, corrected k, range and validity statuses. The grid covers zero/printed/extended subbase thickness, material moduli, subgrade moduli, fractional LS and LS endpoints.
- **45 complete slab results** match exactly, including unrounded and rounded thickness, normalized design inputs, iteration count and residual. These vary reliability, adopted k and design traffic.
- The existing 130 supplied Figure 3.3 golden cases, Figure 3.6 example (540 pci / LS 1 → approximately 169.8 pci), invalid inputs, SI conversion, traffic transfer and saved-case checks remain passing.
- `scripts/kcorr-calculation-baseline.json` stores the reference hashes, deterministic input matrix and aggregate result hashes. `scripts/verify-kcorr-regression.mjs` reruns the comparison in the normal test command; CI does not need access to old Git history.

The intended interface differences remain: manual mode retains the entered kcorr and all foundation inputs; suggested blue constructions are captured at switch-off, remain fixed after input edits, and never write back into kcorr. Changing an entered kcorr legitimately changes slab design. The numerical baseline does not validate project assumptions or the existing extrapolation method.

## Changes made during this review

1. Reuse foundation results/rendering when all relevant foundation values and the mode are unchanged. The cache includes the adopted kcorr value. Relevant edits invalidate it; restore/reset explicitly invalidates it. The slab solver still runs normally with its current inputs.
2. Avoid replacing the valid chart with an empty chart before drawing the valid trace. Reuse the empty reference markup for manual/invalid states.
3. Preload the four existing foundation dependency scripts. Classic script execution order is unchanged, and production URLs use identical cache versions to avoid duplicate requests.
4. Stabilize the kcorr switch click when leaving a field with focus-dependent help. Its checkbox hit area is vertically aligned; pointer-down retains focus until activation, then the switch receives focus. This avoids collapsing help moving the target during a click.
